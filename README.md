# 브릿지 (WHOSE SIDE?) — 역할 추리형 토론 수업

> 학생들이 소외될까 봐 의견을 숨기는 교실에서, 교사는 학생들에게 사회 문제에 대해 자신의 목소리를 내는 역량을 길러 주기 어렵다.

브릿지는 중·고등학교 교사가 사회 문제 토론 수업에 쓰는 웹 게임입니다. **교사가 진행자**, **학생이 참가자**입니다. 학생은 자기 생각을 처음부터 밝히는 대신 **배정받은 역할**을 출발점 삼아 말하고, 비밀 역할·사건 카드·질문·추리·투표로 대화에 참여합니다. AI는 말한 내용을 받아쓰고, 욕설·인신공격을 화면에 나오기 전에 거르고, 역할별로 정리해 교사의 진행을 돕는 데만 씁니다.

- 학생이 고르는 것은 **게임에서 맡고 싶은 역할**입니다. 학생의 실제 정치·사회적 입장으로 저장하거나 표시하지 않습니다.
- **채팅이 없습니다. 학생은 자기 기기의 마이크를 켜고 직접 말합니다.** 입장 발표는 순서대로, 그 뒤로는 질문(Z)과 답변(X)을 먼저 누르는 사람이 말합니다. 방 전체에서 **한 번에 한 명만** 마이크를 켤 수 있고, 말할 수 있는 시간도 정해져 있습니다.
- **말한 내용은 자동으로 정리됩니다.** 입장 발표는 한 사람당 한 장씩 3D 캐릭터가 든 카드와 목록에, 질문과 답변은 "이름 질문/답변"으로 기록됩니다. 학생은 작은 메모를 남길 수 있습니다(내 기기에만 저장).
- **선생님 화면이 토론을 진행합니다.** 교실 화면에 지금 말하는 사람·남은 시간·순서·발언 기록·역할별 정리가 나옵니다.
- 음성은 글로 바꾸는 데만 쓰고 저장하지 않습니다. [음성 기록](#음성-기록) 참고.
- 힌트, 게임 뒤 실제 입장 발표·최종 의견은 없고, 학생 화면에는 점수·평가가 나오지 않습니다. 예외로 **선생님 화면의 결과 단계**에는 수행평가 참고용 선생님 레포트(규칙 기반 평가 기준표, AI가 쓴 학생별 리포트 초안)가 있고, 선생님이 검토하고 고쳐 씁니다.

## 혼자 미리 해 보기 (연습 모드)

```powershell
npm --prefix frontend install
npm run dev
```

http://localhost:5173 → **서버 없이 혼자 연습해 보기**를 누르면 API·Firebase 없이 학생 화면으로 한 판을 끝까지 해 볼 수 있습니다. 함께하는 5명은 역할 카드를 바탕으로 말하는 컴퓨터 연습 상대(AI 아님)로 차례가 되면 짧게 말하고 넘겨 주고, 그중 역할 전환자는 일부러 말을 조금 어색하게 해서 추리할 단서를 남깁니다. 내 차례에는 브라우저 음성 인식(Chrome·Edge)으로 말하거나 직접 입력합니다. 선생님 역할(게임 시작·다음 단계)은 화면 위 연습 진행 바로 직접 합니다. 역할 배정·차례·투표·공개 규칙은 실제 서버와 같고, 표현 점검은 간단한 규칙 검사만 하며 토론 정리는 AI 없이 발언을 모아 보여 주는 간이 정리입니다. 진행은 이 브라우저의 localStorage에만 저장되어 새로고침해도 이어집니다.

주제를 고른 뒤 **선생님 화면 미리보기**로 교사 진행 화면을 바로 열 수 있습니다. 연습 중에는 상단 버튼으로 학생·선생님 화면을 전환하며 같은 게임의 참여 현황, 토론, 결과를 확인할 수 있습니다. 교사 화면에서 일시정지·재개·1분 연장·다음 단계·종료도 연습할 수 있습니다. 학생 입장, 주제·설정 변경, 발언 검토 처리는 실제 방에서만 사용합니다.

연습 모드는 [frontend/src/data/practiceTopics.json](frontend/src/data/practiceTopics.json)의 주제 사본을 씁니다. 주제 JSON을 고친 뒤에는 `npm run content:sync`로 사본을 갱신하세요(백엔드 테스트가 사본이 원본과 같은지 확인합니다).

## 게임 규칙

| 항목 | 내용 |
| --- | --- |
| 인원 | 학생 6~8명 (교사는 참가자가 아닌 진행자) |
| 주제 | 브릿지가 검토한 6개 중 교사가 선택하거나 무작위 (6개 안에서만) |
| 선호 역할 | 학생마다 서로 다른 1순위·2순위 |
| 역할 전환자 | 기본 1명, 교사가 2명으로 설정 가능 |
| 단계 | 대기실(주제·규칙·선호 역할) → 비밀 역할 확인 → 입장 발표 → 사건 공개·질문과 답변 → 반론 → 역할 전환자 투표 → 정체·투표 결과 공개 → 종료 |

### 역할 전환자 선정·배정 (서버에서만)

[backend/app/services/role_assignment.py](backend/app/services/role_assignment.py)

1. 모든 학생의 1순위를 역할별로 셉니다.
2. 가장 많이 선택된 역할을 고릅니다. 동률이면 동률인 역할 중 서버가 무작위로 고릅니다.
3. 그 역할을 1순위로 고른 학생 중에서 역할 전환자를 무작위로 뽑습니다.
4. 역할 전환자는 **본인의 1·2순위를 모두 제외한** 역할 중 하나를 무작위로 받습니다.
5. 나머지 학생은 **본인의 1순위 또는 2순위**를 받습니다. 한 역할에 몰리지 않도록, 무작위 순서로 돌며 1·2순위 중 현재 배정 인원이 적은 쪽을 받습니다(같으면 1순위).

- 역할 전환자 2명 설정인데 후보가 2명 미만이면 시작하지 않고, 교사에게 1명으로 바꾸라고 안내합니다(어느 역할인지·몇 명인지는 밝히지 않음).
- 비선호 역할이 없거나 역할이 4개 미만이면 시작을 막고 원인을 보여 줍니다.
- 배정은 한 번만 합니다. 시작 재요청·재접속으로 다시 뽑지 않습니다. AI는 배정에 관여하지 않습니다.

### 투표와 공개

- 역할 전환자 수만큼 서로 다른 후보를 고릅니다. 자기 자신은 고를 수 없고, 한 번 낸 표는 바꿀 수 없습니다.
- 공개 화면에는 역할 전환자, 득표, 각자의 추리 결과만 나옵니다. 선호 순위는 공개 후에도 나오지 않습니다.
- 최다 득표가 동률이면 승자를 만들지 않고 **동률**로 표시합니다.

### 시간과 미응답

기본 시간은 [backend/app/content/game_config.json](backend/app/content/game_config.json)에 있습니다(역할 확인 45초, 입장 발표 1명당 30초, 사건·질문 240초, 반론 180초, 투표 90초 — 학생 7명 기준 약 13분). 사건·질문과 반론에서 한 번 마이크를 켜면 최대 30초까지 말할 수 있습니다. 교사는 대기실에서 단계 시간을 20~900초, 한 번에 말하는 시간을 10~120초로 바꿀 수 있습니다.

### 누가 언제 말하나

방 전체에서 **한 번에 한 명만** 마이크를 켤 수 있습니다. 서버가 이 잠금을 관리하므로, 두 사람이 동시에 눌러도 한 명만 켜지고 다른 사람은 누가 말하고 있는지 안내를 받습니다. 말하는 동안 다른 학생의 버튼은 꺼져 있습니다.

**입장 발표: 순서대로**

- 내 차례가 오면 **말하기** 버튼이나 Z를 누르고 말합니다. 다시 누르면 끝나고 다음 학생으로 넘어갑니다.
- 차례의 시간이 끝나거나, 학생이 **차례 넘기기**를 누르거나, 교사가 **다음 차례**를 눌러도 넘어갑니다. 모두 말하면 다음 단계로 갑니다.
- 교사는 순서 목록의 이름을 눌러 그 학생에게 바로 차례를 줄 수 있습니다. 이후 순서는 그대로 이어집니다. **건너뛰고 다음 단계**로 남은 차례를 넘길 수 있습니다.

**사건·질문과 반론: 먼저 누르는 사람이**

- 질문하고 싶으면 **질문** 버튼이나 Z, 답하고 싶으면 **답변** 버튼이나 X를 누르고 말합니다. 반론 단계에서는 Z가 **반론**입니다. 다시 누르면 끝납니다.
- 한 번에 말할 수 있는 시간(기본 30초)이 지나면 마이크가 저절로 꺼지고 다음 사람이 누를 수 있습니다. 말하던 기기가 꺼져도 시간이 지나면 풀립니다.
- 단계 전체 시간이 끝나거나 교사가 **다음 단계**를 누르면 넘어갑니다.

**공통**

- 키보드는 눌렀다 떼면 켜진 채로 있고, 1.5초 넘게 누르고 있다 떼면 무전기처럼 그때 꺼집니다. 메모를 쓰는 중에는 Z·X가 글자로만 입력됩니다.
- 일시정지하면 마이크가 꺼집니다. 재개한 뒤 다시 눌러야 합니다. 1분 연장은 입장 발표에서는 현재 차례에, 사건·질문과 반론에서는 단계 전체 시간에 더해집니다.
- 말하지 않은 학생을 막거나 표시하지 않습니다. 역할 확인·투표는 모두 마치면 바로 넘어가고, 미투표는 "투표하지 않음"으로 남습니다.

### 음성 기록과 정리

1. 학생이 처음 마이크를 켤 때 무엇을 듣고 어디로 보내는지 안내가 나오고, 확인해야 켜집니다. **마이크를 쥔 동안만** 그 학생의 기기에서 듣고, 끝나면 마이크를 닫습니다.
2. 기기가 소리를 7~15초 단위(말이 끊기는 곳)로 잘라 서버로 보내면(동시에 최대 3개, 늦게 도착해도 말한 순서대로 기록), 서버가 Gemini로 받아쓰고 바로 버립니다. 소리가 없는 구간은 보내지 않습니다. **음성 파일은 어디에도 저장하지 않습니다.** 서버는 그 순간 마이크를 쥔 학생의 음성만 받습니다.
3. 받아쓴 글은 [표현 점검](#ai-중재)을 거쳐 발언 기록에 남습니다. 발언자와 종류(입장 발표·질문·반론·답변)는 **녹음 당시 마이크를 쥔 학생과 누른 버튼**으로 기록합니다.
4. 정리는 세 가지로 보입니다.
   - **입장 발표 정리**: 한 사람당 한 장. 3D 화면에서 캐릭터가 든 카드의 번호는 이름표의 번호와 같고, 카드를 누르면 크게 읽을 수 있습니다. AI 요약이 오기 전에는 말한 앞부분을 보여 줍니다. 같은 내용이 목록으로도 나옵니다.
   - **질문과 답변**: "이름 질문", "이름 답변"과 말한 내용이 순서대로 쌓입니다.
   - **내 메모**: 학생 기기의 브라우저에만 저장하고 서버로 보내지 않습니다.
5. 토론 정리와 카드 요약은 공개된 발언, 역할 이름, 자리 번호만 AI에 보내 만듭니다. 학생 이름, 역할 전환 여부, 선호는 보내지 않습니다. 평가, 점수, 누가 수상한지는 쓰지 않습니다.
6. 선생님 레포트의 학생별 리포트도 같은 방식(공개된 발언, 역할 이름, 자리 번호)으로 AI에 보냅니다. 결과 공개 뒤 선생님만 요청할 수 있고, 모든 평가 문장은 그 학생 자신의 발언 줄을 근거로 달아야 합니다(다른 학생 발언은 근거에서 빠집니다). 서버에 저장하지 않고 선생님 기기에만 남으며, 점수·등급은 쓰지 않습니다.

알아 둘 한계:

- 말하는 사람의 기기 마이크로 듣기 때문에, 옆에서 끼어든 말은 잘 들어가지 않지만 들어가면 **마이크를 쥔 학생의 발언으로 기록**될 수 있습니다. 음성 인식이 틀릴 수 있으므로 교사가 각 줄을 고치거나 지울 수 있고, 누군가 말하는 동안 놓친 말을 직접 입력할 수 있습니다.
- 기록은 실시간 자막이 아닙니다. 구간을 모아 보내고 받아쓰기와 표현 점검을 거치므로 말한 뒤 화면에 나오기까지 Gemini 응답 속도에 따라 수십 초 걸릴 수 있습니다.
- 마이크는 HTTPS(또는 localhost)에서만 켜집니다. 마이크를 쓸 수 없는 기기도 차례와 잠금은 그대로 쓰고, 말한 내용은 교사가 대신 입력할 수 있습니다. AI가 응답하지 않아도 게임은 그대로 진행됩니다.
- 실제 교실의 소음·거리에서 인식률은 아직 측정하지 않았습니다. 수업 전에 학생 기기로 시험해 보세요. 한 공간에서 여러 기기를 쓰면 다른 사람 목소리가 함께 들어갈 수 있습니다.

**운영 전 확인할 것:** 학생 음성이 외부 서비스(Google Gemini API)로 전송됩니다. 학교의 개인정보 절차(14세 미만은 법정대리인 동의 포함)에 맞는지 확인하고, 입력 데이터를 모델 개선에 쓰지 않는 유료 등급 키를 사용했는지 Google 약관에서 확인하세요. 입장할 때 학생이 적은 이름과 발언 기록은 지금 방 데이터로 Firestore에 계속 남습니다(자동 삭제 없음). 실명을 쓸지는 이 점을 고려해 정해 주세요.

## 이슈 브리핑 영상 (게임 시작 전)

학생은 대기실에서 **이슈 브리핑 영상 → 게임 규칙 → 역할 고르기** 순서로 진행하며, 브리핑을 끝까지 봐야 다음 단계로 넘어갈 수 있습니다. 영상은 가상의 ‘브릿지 뉴스’ 앵커가 전하는 뉴스 형식(오프닝 타이틀, 앵커, 이슈 그래픽, 하단 자막, 출처 티커, 한국어 음성 내레이션, 전체 화면)이며, 교사 대기실 화면에서도 교실에 함께 틀 수 있습니다.

내용은 주제 JSON의 `briefing`(장면·출처)에서만 가져옵니다. 2026년 10월 기준 실제 보도를 요약하고 장면마다 출처(언론사·날짜·링크)를 붙였으며, 서버가 시작할 때 모든 장면의 출처가 목록에 있는지 검증합니다. AI가 영상 내용을 만들지 않습니다. **수업 전에 출처 기사를 확인해 주세요.** 일부 출처는 날짜 표기가 불분명해 데이터에 `날짜 확인 필요`로 남겨 두었습니다.

### 영상 내레이션 (AI 합성 음성)

브리핑(앵커·리포터 재연)과 게임 규칙 영상(진행자)의 음성은 Gemini TTS로 **미리 만들어 둔 MP3**를 재생합니다(`frontend/public/audio/briefing/`, 목록 `frontend/src/data/briefingAudio.json`). 브라우저에서 AI를 부르지 않으며, 원고와 음성이 다르거나 파일이 없으면 그 장면은 자막만 나옵니다. 원고(주제 JSON의 `briefing`, `frontend/src/data/rulesVideo.json`)를 고친 뒤에는 바뀐 장면만 다시 만듭니다.

```powershell
pip install lameenc
python scripts/generate-briefing-audio.py   # backend/.env 의 GEMINI_API_KEY 사용
```

무료 등급은 TTS 모델마다 하루 요청 수가 적어, 스크립트가 다음 모델로 넘어가며 만들고 남은 장면은 다음 실행 때 채웁니다. 화면 장면(교실·복도·급식실 등)은 실제 사진이 아닌 직접 그린 일러스트이며 ‘이해를 돕기 위한 그림’으로 표시됩니다.

## AI 중재

[backend/app/services/moderation.py](backend/app/services/moderation.py)

받아쓴 말과 교사가 입력한 말은 공유 화면과 학생 기기에 나오기 전에 서버에서 검사합니다.

1. **규칙 검사** — 분명한 욕설·인신공격만 잡습니다. 오탐을 줄이도록 정밀도 위주로 만들었습니다("음식을 씹다", "폰이 꺼져서", "시발점"은 통과).
2. **AI 검사** (Gemini, 서버에서만 호출) — 욕설·특정인을 향한 인신공격·조롱인지만 판단합니다. 의견 차이와 반론은 막지 않고, 주장의 옳고 그름이나 학생 성향은 판단하지 않으며, 문장을 고쳐 쓰지 않습니다.
3. 걸리면 공유 기록에 넣지 않고 교사의 "표현 점검 기록"에만 남깁니다. 자리표시도 남기지 않아 공개 낙인이 없고, 자동 퇴장도 없습니다. 말은 이미 교실에서 들렸으므로 지도는 교사가 판단합니다.
4. AI가 응답하지 않으면 한 번 재시도한 뒤 **교사 확인 대기**로 둡니다. 검수 없이 자동 공개하지 않습니다. 교사는 "공개하기"(원래 순서 자리로 들어감)나 "공개하지 않기"를 고릅니다.

교사 화면에는 표현 점검 내용이 있으니 프로젝터로 띄울 때는 **교실 화면으로 크게**를 누르세요. 교사 패널이 숨겨지고 확인할 발언 수만 표시됩니다.

학생에게는 주제 데이터에 있는 질문 예시만 보여 줍니다. AI가 주장문을 써 주거나 정답을 말하지 않습니다.

## 비밀 유지 구조

클라이언트는 Firestore에 쓸 수 없고, 읽을 수 있는 문서도 역할에 따라 다릅니다([firestore.rules](firestore.rules)).

| 문서 | 내용 | 읽기 |
| --- | --- | --- |
| `rooms/{id}` | 주제(사건 카드·교사 안내 제외), 단계, 타이머, 지금 마이크를 쥔 사람, 설정, 사건 단계 이후 사건 카드 | 학생·교사 |
| `participants/{uid}` | 이름, 자리, 역할 선택 완료 여부, 제출 표시, 역할 확인 뒤 공개된 역할 | 학생·교사 |
| `publicRounds/*` | 표현 점검을 통과한 발언 기록, 토론 정리, 투표 후 결과 | 학생·교사 |
| `privatePlayers/{uid}` | 선호 1·2순위, 배정 역할, 역할 전환 여부, 내 표, 중재 안내 | **그 학생만** (교사도 불가) |
| `host/state` | 표현 점검 기록, 교사용 진행 안내 | **교사만** |
| `internal/state` | 전체 상태(투표 전 표 포함) | 서버만 |

- 방을 만든 익명 계정이 교사입니다. 교사용 API는 서버가 이 계정인지 확인하고, 학생용 API는 참가 학생인지 확인합니다.
- 교사 화면에도 학생별 선호 순위·집계·역할 전환 여부는 결과 공개 전까지 나오지 않습니다(프로젝터로 띄워도 안전). 표현 점검 기록은 기본으로 접혀 있습니다.
- 재접속하면 같은 익명 계정으로 서버에 저장된 단계와 역할로 돌아옵니다. 브라우저에는 방 ID만 저장합니다.

## 로컬 실행

필요 환경: Node.js 22.12+, Python 3.11–3.13, Java 21+ (Firebase Emulator).

팀의 공유 브랜치는 `main`입니다. 기존 저장소에서 최신 코드를 받으려면 다음을 실행하세요.

```powershell
git switch main
git pull --ff-only origin main
```

각자의 `backend/.env`와 `frontend/.env`는 Git에 포함되지 않습니다. 처음에는 아래 예시 파일을 복사하고, 이미 있는 `.env`는 유지하세요. AI 키와 Firebase 서비스 계정은 각자 설정합니다.

처음 한 번:

```powershell
npm install
npm --prefix frontend install
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -e './backend[test]'
Copy-Item backend/.env.example backend/.env

```

터미널 세 개에서:

```powershell
npm run emulators                                   # 1. Firebase Auth·Firestore Emulator
cd backend; .venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000   # 2. API
npm run dev                                         # 3. 웹 (http://localhost:5173)
```

VS Code에서는 `백엔드 (FastAPI · backend/.env)`를 선택하고 F5를 누르면 `backend/.env`에 설정한 Firebase에 연결합니다. 프런트엔드까지 함께 실행하려면 `전체 실행 (백엔드 + 프론트)`를 선택하세요. 위의 에뮬레이터 설정을 사용하는 경우에는 `전체 실행 (Firebase 에뮬레이터 사용)`을 선택하면 에뮬레이터도 함께 시작합니다. 이미 `npm run dev`로 프런트엔드를 실행했다면 F5에서는 백엔드만 실행하세요.

교사는 **선생님 → 주제 선택 → 게임 방 만들기**, 학생은 QR이나 **학생 → 방 코드**로 들어옵니다. 같은 브라우저 프로필의 탭은 같은 익명 계정이므로, 혼자 시험할 때는 교사 1개 + 학생 6개의 분리된 브라우저 프로필(또는 시크릿 창)을 쓰세요. 교사 계정으로는 학생 입장이 막혀 있습니다.

`GEMINI_API_KEY` 없이 로컬에서 시험하려면 `backend/.env`에 `MODERATION_MODE=rules`를 두세요(규칙 검사만 사용, 운영 환경에서는 서버가 거부). 키가 있으면 기본값 `ai`로 둡니다. `ai` 모드인데 키가 없거나 AI가 응답하지 않으면 발언은 교사 확인 뒤에만 공개됩니다. 받아쓰기와 토론 정리에는 키가 필요하며, 키가 없으면 교사가 직접 입력해 진행할 수 있습니다.

Gemini를 사용하려면 `AI_PROVIDER=gemini`와 `GEMINI_API_KEY`를 설정하고 `MODERATION_MODE=ai`로 바꾸세요. Vertex AI를 사용하려면 `AI_PROVIDER=vertex`, `VERTEX_API_KEY`, `VERTEX_MODEL`을 설정합니다. 음성 받아쓰기·표현 점검·토론 정리·학생별 AI 리포트는 선택한 제공자를 사용하며, 브리핑 음성 생성 스크립트는 별도로 `GEMINI_API_KEY`를 사용합니다. 설정 변경 후에는 백엔드를 재시작하세요.

실제 Firebase에 연결할 때는 프런트엔드와 백엔드의 프로젝트 ID를 맞추고 `VITE_USE_FIREBASE_EMULATORS=false`로 설정합니다. 백엔드의 에뮬레이터 호스트 두 항목은 비우거나 삭제하고, 관리자 인증은 `FIREBASE_SERVICE_ACCOUNT_JSON_BASE64` 또는 `GOOGLE_APPLICATION_CREDENTIALS`에 서비스 계정 JSON의 절대 경로를 지정해 설정하세요. 키 파일은 Git에 올리지 않습니다.

| `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID` | Firebase Web App 설정값 |
| `VITE_API_BASE_URL` | 백엔드 배포 주소 (예: `https://bridge-api.vercel.app`) |
| `VITE_USE_FIREBASE_EMULATORS` | `false` |
| `VITE_KAKAO_REST_API_KEY` | 카카오 REST API 키 (비우면 카카오 로그인 버튼 숨김) |

**백엔드 환경변수** (서버 전용, `VITE_`에 넣지 말 것)

| 이름 | 값 |
| --- | --- |
| `ENVIRONMENT` | `production` |
| `FIREBASE_PROJECT_ID` | Firebase 프로젝트 ID |
| `FIREBASE_SERVICE_ACCOUNT_JSON_BASE64` | 서비스 계정 JSON 전체를 Base64로 인코딩한 값 |
| `GOOGLE_APPLICATION_CREDENTIALS` | 파일 기반 인증을 쓸 때 서비스 계정 JSON의 절대 경로 |
| `ALLOWED_ORIGINS` | 프런트엔드 주소 (쉼표로 여러 개) |
| `GEMINI_API_KEY` | 받아쓰기·표현 점검·토론 정리용 키 |
| `GEMINI_MODEL` | 선택, 기본 `gemini-3.5-flash-lite` |
| `AI_PROVIDER` | `gemini`(기본) 또는 `vertex` |
| `VERTEX_API_KEY`, `VERTEX_MODEL` | `AI_PROVIDER=vertex`일 때 서버용 키와 모델 ID |
| `MODERATION_MODE` | `ai` (기본값, 운영에서는 `rules` 불가) |
| `KAKAO_REST_API_KEY` | 선생님 카카오 로그인용 REST API 키 |
| `KAKAO_CLIENT_SECRET` | 카카오 Client Secret을 켠 경우에만 |

운영에는 `FIRESTORE_EMULATOR_HOST`·`FIREBASE_AUTH_EMULATOR_HOST`를 **넣지 않습니다**(있으면 서버가 시작을 거부).

배포 순서:

1. Firebase 프로젝트 생성 → Firestore 생성 → Authentication에서 **익명**(학생)과 **Google**(선생님) 로그인 사용 → Web App 등록.
2. 보안 규칙 배포: `npx firebase deploy --only firestore:rules,firestore:indexes --project YOUR_PROJECT_ID`
3. Vercel 백엔드 프로젝트 생성·환경변수 등록·배포 → `https://백엔드주소/health`에서 `"moderation": "ai"` 확인.
4. Vercel 프런트엔드 프로젝트 생성·`VITE_API_BASE_URL`에 백엔드 주소 등록·배포.
5. 백엔드 `ALLOWED_ORIGINS`와 Firebase Authentication 승인 도메인에 프런트엔드 주소 추가 → 백엔드 재배포.
6. Kakao Developers 카카오 로그인 Redirect URI에 `https://프런트엔드주소/auth/kakao` 등록.

자세한 API·데이터 구조는 [backend/README.backend.md](backend/README.backend.md)에 있습니다.

frontend/src/
  app/              라우팅

  features/
    room/           실시간 구독(useRoom) · 방 코드·QR · 재접속용 방 ID

    discussion/     학생 마이크(Z·X) · 차례 표시 · 입장 발표 정리 · 질문과 답변 · 메모 · 발언 기록 · 토론 정리
    voting/         투표 · 결과 공개

  services/         게임 진행 · 단계·차례 엔진 · 역할 배정 · 투표 · 중재 · 받아쓰기·정리 · AI 클라이언트

tests/              보안 규칙 · 브라우저 E2E
