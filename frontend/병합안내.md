# 병합 안내: `front` ↔ `teacher-screen-detail`

작성: 2026-11-08 · 대상: 두 브랜치를 합치는 사람(사람 또는 AI)

- `front`: 게임 규칙, 학생 화면, 백엔드 담당
- `teacher-screen-detail`: 선생님 화면 디자인 담당(단계별 바로가기, 단계 메모, 수행평가 레포트, 진행된 토론 목록)
- 두 브랜치가 갈라진 지점: `0dfceab`

## 1. 우선순위 (충돌 나면 이대로)

| 영역 | 우선 | 설명 |
|---|---|---|
| 선생님 화면 디자인 (배치, 패널, 레포트, 메모, 토론 목록) | **teacher-screen-detail** | 팀원 디자인을 그대로 쓴다. |
| 선생님 화면의 **전체 화면 버튼과 교실 화면** | **front** | 이 부분만 예외로 `front` 디자인을 쓴다. 아래 2번 참고. |
| 백엔드 (`backend/` 전체) | **front** | `teacher-screen-detail`은 백엔드를 바꾸지 않았다. 충돌 없이 `front` 것이 들어가야 한다. |
| 게임 규칙에 묶인 프런트 코드 (단계 순서, 질의응답, 투표, 자동 시작, 연습 엔진 규칙) | **front** | 백엔드와 같이 움직여야 한다. 팀원 쪽 디자인을 살리더라도 이 동작은 `front`에 맞춘다. |
| 학생 화면 | **front** | 팀원 브랜치는 학생 화면을 바꾸지 않았다. |

## 2. 전체 화면 버튼: `front` 디자인을 쓴다

`frontend/src/pages/TeacherRoomPage.tsx`에서 아래만 `front` 것으로 가져온다. 나머지 화면 배치는 팀원 것을 쓴다.

- **버튼**: 위쪽 바(`teacher-top`)의 `data-testid="present-toggle"` 버튼. 글자는 "교실 화면 (전체 화면)"이고, 대기실이 아닐 때만 보인다.
- **동작**: `openPresent` / `closePresent`와 `fullscreenchange` 감지(`useEffect`). 누르면 브라우저 진짜 전체 화면(`requestFullscreen`)이 되고, Esc로 전체 화면을 나가면 교실 화면도 닫힌다.
- **교실 화면**: 같은 파일 아래쪽의 `ClassScreen` 컴포넌트. 단계 이름·남은 시간·"나가기" 버튼, 발표자 표시(`SpeakerStage`), 원탁을 위에서 보는 화면(`TableView overview`), 결과 단계에서는 결과 요약(`RevealSummary`)을 띄운다.
- **CSS**: `frontend/src/styles/discussion.css`의 `.class-screen`, `.class-screen-top`, `.class-screen-table`, `.class-screen-result` 규칙.

버리는 것(팀원 브랜치의 예전 방식):
- `setPresent((v) => !v)`로 켜고 끄는 토글, "교실 화면으로 크게" / "선생님 패널 보기" 글자
- `<main>`의 `present` 클래스(`teacher-room ... present`). 교실 화면이 이제 별도 화면이라 필요 없다.
- `present &&` 조건이 붙은 확인할 발언 배지. `front`처럼 `toReview > 0`이면 항상 보인다.

## 4. 팀원 코드에서 `front`에 맞춰 고칠 곳

`front`에서 규칙과 이름이 바뀌어, 팀원 코드를 그대로 두면 빌드가 깨지거나 동작이 어긋난다.

1. **`GameSummary`가 없어졌다.** `ParticipationBoard.tsx`에서 `GameSummary`는 빠지고 `ParticipationGrid`(학생별 참여 카드)로 바뀌었다. 팀원의 `import ParticipationBoard, { GameSummary }`와 `{phase === "ended" && <GameSummary .../>}`는 `front`처럼 `ParticipationGrid`로 바꾸거나 지운다.
2. **결과 요약 이름**: `front`의 선생님 화면은 `RevealView`(학생용) 대신 `RevealSummary`를 쓴다. 둘 다 `RevealView.tsx`에 있다. 팀원 디자인에서 쓰는 쪽에 맞추되, 교실 화면(`ClassScreen`)은 `RevealSummary`를 쓴다.
3. **투표는 모두 투표해도 끝나지 않는다.** `createPracticeAt`의 투표 단계는 모든 표를 넣은 뒤 `act(s, "sync", ...)`로 결과로 넘어가길 기대한다. 이제는 넘어가지 않아서 반복문이 결과 단계에 닿지 못한다. 이 줄을 `act(s, "next", {}, t)`로 바꾼다(주석 "With every vote in, settling moves on…"도 지운다).
4. **입장 발표 뒤 질의응답이 생겼다.** 마지막 발표가 끝나면 `statement` 단계 안에서 `turn.stage === "qa"`가 되고 `turn.uid`는 `null`이다. `createPracticeAt`의 발표 처리(`room.turn?.uid === ME`)는 문제없지만, 질의응답 시간에는 `next`로 넘겨야 사건 단계로 간다.
5. **반론 단계는 없다.** `previewLine`의 마지막 `return`(반론 문장)은 더 쓰이지 않는다. 지워도 되고 그냥 둬도 된다. 단계 바로가기 목록(`PHASE_ORDER`)에는 이미 반론이 없다.
6. **`PhaseMemo`·레포트의 단계 목록**: 단계별로 메모나 레포트를 나눈다면 `rebuttal`을 넣지 않는다. 예전 기록 호환 때문에 `Phase` 타입에는 `"rebuttal"`이 남아 있다.

## 5. `front`에서 바뀐 것 (`0dfceab` 이후)

### 게임 규칙 (백엔드 + 프런트)
- **반론 단계 삭제**: `lobby → role → statement → event → vote → reveal → ended`. 사건·질문 기본 시간 420초.
- **자동 시작**: 6~8명이 모두 역할을 고르면 3초 뒤 서버가 스스로 시작한다. 선생님 화면이 닫혀 있어도 된다. 그 사이 학생이 들어오거나, 내보내지거나, 주제가 바뀌면 취소된다.
- **입장 발표 뒤 질의응답**: 모두 발표한 뒤 같은 단계에서 90초(`game_config.json`의 `qaSeconds`) 동안 누구나 질문·답변 마이크를 켠다.
- **투표 바꾸기**: 투표 시간 안에는 다시 보내면 새 표로 바뀐다. 시간이 끝나거나 선생님이 넘길 때만 결과로 간다. 학생 화면은 후보를 다 고를 때마다 바로 보낸다.

### 백엔드 파일
- `backend/app/services/phase_engine.py`: 단계 순서, 질의응답(`in_qa`, `mic_kinds`, `start_qa`), 투표 조기 종료 제거
- `backend/app/services/game.py`: 자동 시작(`_arm_start`, `_auto_start`), 질의응답 마이크 규칙, 투표 덮어쓰기
- `backend/app/content/game_config.json`: `event` 420, `rebuttal` 삭제, `qaSeconds` 90
- `backend/app/models/requests.py`: `phaseSeconds.rebuttal`은 받아도 무시
- `backend/README.backend.md`, `backend/tests/*`: 새 규칙에 맞춤(테스트 92개 통과)

### 프런트 화면
- **학생 화면**: 학생 기기 마이크(Z·X)와 발언 잠금, 카드형 역할 확인 팝업, 역할 카드 드래그 선택, 원탁 카드와 가리키기 투표, 캐릭터 결과 팝업, 사건 카드 팝업(×나 Esc로만 닫힘), 메모 중심 토론
- **원탁 카드**: 캐릭터가 손에 카드를 들던 3D 연출과 화면 아래 내 팔을 없앰(팔은 투표로 가리킬 때만 보임). 원탁을 배경으로 두고, 세로로 긴 카드를 아래쪽에 한 줄로 띄움(`features/game/CardStrip.tsx`). 카드에는 요약 전체가 잘리지 않고 보이고, 누르면 그 사람의 음성 기록 전체가 열림. 역할 확인 단계에서는 카드 줄 대신 역할 확인 팝업만 보임.
- **선생님 화면**: 전체 화면 교실 화면(`ClassScreen`), 학생별 참여 카드(`ParticipationGrid`), 자동 시작 카운트다운
- **연습 모드**: 위 규칙과 똑같이 동작(질의응답, 투표 바꾸기, 반론 없음)
- **임시 처리 삭제**: 반론 단계 자동 건너뛰기, 투표를 마지막 2초에 보내던 처리

자세한 날짜별 기록은 `frontend/수정이력.md`, 백엔드 요청과 처리 상태는 `frontend/백엔드수정요청.md`에 있다.

## 6. 병합 뒤 확인

1. `cd frontend && npx tsc -b && npx vite build`
2. `cd backend && .venv/bin/python -m pytest -q`
3. 연습 모드 선생님 화면에서 단계 바로가기로 "투표", "결과"를 열었을 때 멈추지 않고 열리는지(4-3번)
4. 선생님 화면에서 "교실 화면 (전체 화면)"을 눌러 진짜 전체 화면이 되는지, Esc로 나가면 교실 화면도 닫히는지
5. 대기실에서 모두 역할을 고르면 3초 뒤 시작하는지, 투표를 바꾼 뒤 시간이 끝나면 결과에 바뀐 표가 반영되는지
