# 백엔드 수정 요청

## 1. 반론(rebuttal) 단계 없애기 (2026-11-07)

- 관련 기능/API: 게임 단계 진행. `backend/app/services/phase_engine.py`의 `PHASES`, `TIMED_PHASES`, `SPEAKING_PHASES`, `MIC_KINDS`, `backend/app/content/game_config.json`의 `phaseSeconds.rebuttal`, `backend/app/models/requests.py`의 `PhaseSeconds.rebuttal`
- 현재 동작: 사건·질문(`event`)이 끝나면 항상 반론(`rebuttal`)으로 넘어간 뒤 투표(`vote`)로 간다.
- 필요한 변경: 단계 순서를 `lobby → role → statement → event → vote → reveal → ended`로 바꾼다. 반론 시간만큼 사건·질문 기본 시간을 늘린다(예: `event` 240초 → 420초).
- 이유: 질문·답변이 있으니 반론 시간이 따로 필요 없다는 수업 피드백. 그 시간은 질문·답변에 쓴다.
- 프런트엔드에 미치는 영향:
  - 프런트엔드는 반론 단계를 화면 단계 목록과 설정·참여 현황에서 이미 뺐다. 새 방을 만들 때 `phaseSeconds.event`를 420초로 보낸다.
  - 임시 처리: 서버가 반론 단계로 들어가면 **선생님 화면이** 곧바로 `skip-phase`를 보내 투표로 넘긴다(`frontend/src/pages/TeacherRoomPage.tsx`). 그래서 선생님 화면이 닫혀 있으면 반론 단계가 그대로 진행되고, 학생 화면에는 그 사이 "곧 투표로 넘어가요."만 보인다.
  - 백엔드가 바뀌면 이 임시 처리는 지워도 된다. `Phase` 타입의 `"rebuttal"`은 예전 기록과 호환되도록 남겨 둬도 무방하다.
- 확인 방법: 방을 만들어 사건·질문 단계에서 선생님이 "다음"을 누르거나 시간이 끝나면, 반론을 거치지 않고 투표 단계(`phase: "vote"`)로 바로 넘어가는지 본다.

## 2. 모두 역할을 고르면 자동 시작 (2026-11-07, 선택)

- 관련 기능/API: `host start` 액션 (`backend/app/services/game.py`의 `_host_start`)
- 현재 동작: 게임 시작은 선생님의 `start` 요청으로만 된다.
- 프런트엔드 처리: 모두 고르면 선생님 화면이 3초 카운트다운 뒤 `start`를 보낸다. 학생 화면은 같은 카운트다운만 보여 준다.
- 필요한 변경(선택): 마지막 학생이 `preferences`를 제출했을 때 인원 조건을 만족하면 서버가 3초 뒤 스스로 시작하게 하면, 선생님 화면이 닫혀 있어도 시작된다.
- 확인 방법: 선생님 화면을 닫은 채 학생 6명이 모두 역할을 고르면 3초 뒤 `phase: "role"`이 되는지 본다.
