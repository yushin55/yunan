# 백엔드 수정 요청

## 1. 반론(rebuttal) 단계 없애기 (2026-11-07)

- 관련 기능/API: 게임 단계 진행. `backend/app/services/phase_engine.py`의 `PHASES`, `TIMED_PHASES`, `SPEAKING_PHASES`, `MIC_KINDS`, `backend/app/content/game_config.json`의 `phaseSeconds.rebuttal`, `backend/app/models/requests.py`의 `PhaseSeconds.rebuttal`
- 현재 동작: 사건·질문(`event`)이 끝나면 항상 반론(`rebuttal`)으로 넘어간 뒤 투표(`vote`)로 간다.
- 필요한 변경: 단계 순서를 `lobby → role → statement → event → vote → reveal → ended`로 바꾼다. 반론 시간만큼 사건·질문 기본 시간을 늘린다(예: `event` 240초 → 420초).
- 이유: 질문·답변이 있으니 반론 시간이 따로 필요 없다는 수업 피드백. 그 시간은 질문·답변에 쓴다.
- 프런트엔드에 미치는 영향:
  - 프런트엔드는 반론 단계를 화면 단계 목록과 설정·참여 현황에서 이미 뺐다. 새 방을 만들 때 `phaseSeconds.event`를 420초로 보낸다.
  - 임시 처리: 서버가 반론 단계로 들어가면 **선생님 화면이** 곧바로 `skip-phase`를 보내 투표로 넘긴다(`frontend/src/pages/TeacherRoomPage.tsx`). 그래서 선생님 화면이 닫혀 있으면 반론 단계가 그대로 진행되고, 학생 화면에는 그 사이 "곧 투표로 넘어가요."만 보인다.
  - 백엔드가 바뀌면 이 임시 처리는 지워도 된다. `Phase` 타입의 `"rebuttal"`은 예전 기록과 호환되도록 남겨 둬도 무방하다.
- 확인 방법: 방을 만들어 사건·질문 단계에서 선생님이 "다음"을 누르거나 시간이 끝나면, 반론을 거치지 않고 투표 단계(`phase: "vote"`)로 바로 넘어가는지 본다.

## 2. 모두 역할을 고르면 자동 시작 (2026-11-07, 선택)

- 관련 기능/API: `host start` 액션 (`backend/app/services/game.py`의 `_host_start`)
- 현재 동작: 게임 시작은 선생님의 `start` 요청으로만 된다.
- 프런트엔드 처리: 모두 고르면 선생님 화면이 3초 카운트다운 뒤 `start`를 보낸다. 학생 화면은 같은 카운트다운만 보여 준다.
- 필요한 변경(선택): 마지막 학생이 `preferences`를 제출했을 때 인원 조건을 만족하면 서버가 3초 뒤 스스로 시작하게 하면, 선생님 화면이 닫혀 있어도 시작된다.
- 확인 방법: 선생님 화면을 닫은 채 학생 6명이 모두 역할을 고르면 3초 뒤 `phase: "role"`이 되는지 본다.

## 3. 입장 발표 뒤 질의응답 (2026-11-08)

- 관련 기능/API: 입장 발표 단계의 차례(`turn`), 마이크(`mic-on`), `phase_engine.py`의 `MIC_KINDS["statement"]`, `transition`/`next_turn`
- 현재 동작: 입장 발표 단계에서는 차례인 학생 한 명만 `statement`로 말할 수 있고, 마지막 학생이 끝나면 바로 사건 단계로 넘어간다.
- 필요한 변경: 모든 학생의 입장 발표가 끝나면 사건 단계로 넘어가기 전에 같은 `statement` 단계 안에서 질의응답 시간(예: 90초)을 둔다. 이때 `room.turn.stage = "qa"`로 표시하고(발표 중에는 `"speech"` 또는 없음), 누구나 `question`/`answer`로 마이크를 켤 수 있게 한다(사건 단계와 같은 마이크 규칙, 1회 `micSeconds`). 질의응답 시간이 끝나거나 선생님이 넘기면 사건 단계로 간다.
- 이유: 수업 피드백 "입장 발표를 모두 한 다음, 각 입장에 대해 질의응답하기".
- 프런트엔드에 미치는 영향: 프런트엔드는 이미 `turn.stage === "qa"`일 때 질문/답변 버튼과 질문 목록("입장 발표에 대한 질문")을 보여 주고, 발표자에게 카메라를 맞추지 않는다(`src/features/game/phases.ts`의 `micKinds`, `openFloor`). 연습 모드에서는 이대로 동작한다. 실제 방은 서버가 이 단계를 보내 주면 바로 동작한다.
- 확인 방법: 입장 발표에서 마지막 학생이 끝나면 `phase`는 `statement`인 채로 `turn.stage`가 `"qa"`가 되고, 아무 학생이나 `mic-on`(`question`)이 되며, 시간이 끝나면 `event`로 넘어가는지 본다.

## 4. 투표 시간 안에는 투표 바꾸기 (2026-11-08)

- 관련 기능/API: 학생 `vote` 액션(`backend/app/services/game.py`), `phase_engine.py`의 `all_submitted`
- 현재 동작: 한 번 투표하면 "이미 투표했어요. 투표는 바꿀 수 없어요."(409)로 막히고, 모두 투표하면 시간이 남아도 바로 결과로 넘어간다.
- 필요한 변경: 투표 단계 동안에는 같은 학생의 `vote`를 다시 받아 덮어쓴다. 투표 단계는 시간이 끝날 때(또는 선생님이 넘길 때)만 끝나게 `all_submitted`의 `vote` 조건을 뺀다.
- 이유: 수업 피드백 "투표 시간 동안은 자유롭게 투표를 바꿀 수 있고, 투표 시간이 끝나면 그때 끝난다."
- 프런트엔드에 미치는 영향: 지금은 학생 화면이 고른 사람을 기기에 들고 있다가 남은 시간 2초에 한 번만 보낸다(`frontend/src/pages/StudentRoomPage.tsx`, `ponytail:` 주석). 그래서 선생님이 시간 전에 다음 단계로 넘기거나 그 순간 연결이 끊기면 그 학생의 표가 빠진다. 백엔드가 바뀌면 가리킬 때마다 바로 보내도록 바꾸면 된다.
- 확인 방법: 투표 단계에서 한 학생이 A에게 투표한 뒤 B로 다시 투표하면 200이 오고 결과에 B가 반영되는지, 모두 투표해도 시간이 끝날 때까지 투표 단계가 유지되는지 본다.
